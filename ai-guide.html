可以直接交給 AI 的需求

請先讀取本頁的素材與地圖 JSON，並查看圖片圖鑑及必要的原始 PNG。幫我規劃家園：每種主題集中成一個場景，盡量運用整張地圖，保留連通道路，每種能同時存在的家具至少放一個。聖杯、武道、爭霸各選一個獎勵。依家具用途設計，房門朝道路、攤位前留空、座位朝活動中心；圍欄圍出有開口的庭院，高樹不要擋門。需要時使用鏡像。最後提供可直接用「讀取配置」載入的 V31 JSON，先檢查越界、重疊、地板支撐、互斥和入口連通，並說明你的場景安排。

座標與圖片

  • 地圖每個區塊為 16×16，map.rows 的每列為 [起始欄,結束欄)，使用 0 起算、結束不含。物件 x,y 是占地矩形左上角。必須讓整個占地都在有效範圍內。
  • 螢幕投影為 screenX=10*(x+y)、screenY=5*(y-x)。W 正面是 x 減少方向，畫面左下；S 正面是 y 增加方向，畫面右下。
  • defaultFacing 是已判讀的原圖正面提示；仍請看圖確認實際門口。mirror:true 會水平鏡像，讓 W 與 S 互換。flip:true 交換長寬並翻面；所有現有素材都是正方形，一般使用 flip:false。
  • 只有這兩個可見正面，不能生成背面或另外兩個視角。圖片角度、縮放不會縮小碰撞占地。PNG 的透明空白、屋頂和樹冠也不能當成可走範圍的判據。
  • 圖片路徑以 JSON 本身所在的 AI資料 資料夾為基準；圖鑑的連結可直接開啟。不要把 1254×1254 畫布尺寸當成家具占地。

必須遵守的擺放規則

  • 普通家具占地不可互相重疊；普通地板可以在家具下面，但地板彼此不能重疊。相鄰地板以 4 格對齊比較容易拼接。草地 grass_tile 是清除地板工具，不必實際放置。
  • isThemeBuilding:true 是同一素材 ID 限一棟，不是整個主題只能有一棟。三種 exclusiveGroup 分別限一件獎勵，不能同一組放多個名次。
  • requiresWater:true 的三艘船，整個占地必須鋪滿 water_tile。水池上不能放其他家具。名稱有「池」的家具不一定是水池，請依 kind。
  • needsStarFloor:true 的異星家具，整個占地須鋪滿 item_7937 星空窗；item_7936 木星磚為普通地板，不能承載它們。星空窗上不能放其他主題的家具。
  • 一般圍欄的實際碰撞是沿中線、半個占地寬的帶狀。fenceBase.y1<y0 時原向中線沿 x，否則沿 y；鏡像後交換方向。圍欄只能端點接端點，不可重疊牆身或形成 T 字、交叉。可以沿家具共同邊界，不能穿入家具內部。
  • 有 wall.path 的翠瓦圍牆使用該正規化折線；鏡像以 (u,v)→(1-v,1-u) 轉換。有 wall.noOverlap 時，完整占地不能與其他圍牆占地重疊。
  • 全局道路與每個需要進出的門口要連通。建議主路 4 格、門前至少 4 格淨空。圍欄需有開口。橋、牌樓目前仍有家具占地，請預留旁路，不要假設程式能從其占地中穿過。

交付檔案格式

下載空白配置，保留 format、version:31、assetMode:catalog 和完整 map；將擺放記錄填入 placed。每個物件的 id 必須唯一，asset 必須使用清單中的 ID。

{ "id":"mushroom-home-1", "asset":"item_7893", "x":100, "y":32, "flip":false, "mirror":true }

assetOverrides:[] 表示沿用網站素材資料。一般設計不需要帶圖片或複製全部素材。若延續使用者配置，請保留原有 assetOverrides，以免遺失素材校正；自訂圖片可能保存在其中。完成後交付 UTF-8 JSON，使用者在工坊按「讀取配置」即可載入。

只通過 JSON 結構檢查不代表可放置；工坊會再檢查地圖、碰撞與支撐。若目前 AI 無法讀圖片，請清楚說明尚未完成視覺判讀，不能宣稱已確認門口與遮擋。
